# Endpoint Registry

A cross-reference of every backend route registered in DataCats against the frontend
call sites that actually use it. Generated by auditing [`backend/server.js`](backend/server.js),
all files under [`backend/routes/`](backend/routes/), and every API call under `frontend/src/`.

**Method:** routes were enumerated from each `router.*` declaration plus the mount prefixes in
`server.js`. Frontend calls were resolved to full URLs, accounting for the two different
`fetchWithAuth` helpers — [`utils/apiHelpers.js`](frontend/src/utils/apiHelpers.js) *prepends*
`/api/v1`, while [`utils/api.js`](frontend/src/utils/api.js) and raw `fetch()` use the URL as-is.
The dynamic `metric` prop in `MetricsCard` was resolved to its four call-site values
(`mrr`, `churn`, `active-users`, `nps`).

**Status legend:**
- ✅ **Live** — called from the current frontend.
- ⚠️ **Zombie** — labeled "DEAD" in code, but the UI actually still calls it. Live in practice.
- ❌ **Dead** — registered but never called from the frontend. Removal candidate.
- 🔧 **Ops** — not called by the SPA by design (infra/health check). Not dead; do not remove.

## "Not so dead" — zombie endpoints (2)

These carry `// DEAD ENDPOINT` comments in the source, but the live UI still calls them, so the
comments are wrong. **Do not remove without first fixing the caller.**

- **`GET /api/v1/legacy/export/csv`** — the "Preview export data" button in
  [ApiKeyManager.jsx:57](frontend/src/components/settings/ApiKeyManager.jsx#L57) hits this legacy
  route. The source comment at [legacyExport.js:9](backend/routes/legacyExport.js#L9) even notes
  the UI calls it "accidentally."
- **`POST /api/v1/legacy/export/bulk`** — the "Export users" button in
  [UserExportButton.jsx:16](frontend/src/components/users/UserExportButton.jsx#L16) posts to it.
  The "DEAD ENDPOINT" comment at [legacyExport.js:27](backend/routes/legacyExport.js#L27) is stale.

Because of these two, the `/api/v1/legacy/export` mount and its router must stay; only the
`/pdf` route within it is safe to delete.

## Ops endpoint (not dead)

- **`GET /health`** — intentionally not called from the SPA; it's an infra/monitoring probe.
  It shows up as "uncalled by frontend" but should not be removed.
