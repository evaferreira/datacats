**Clip 4: Detecting Side Effects Early**   (~5 minutes)

Some regressions appear only after deployment. We will discuss staged rollouts, canary releases, logs, monitoring, error rates, performance baselines, and user feedback loops, using AI to analyze logs, group errors, compare release metrics, and highlight suspicious changes quickly.

                **Demo:** None — this clip is slides only.

### Slide 1

**Detecting side effects early** *(section title)*

Script note: *No matter how much we test, sometimes regressions slip. What matters in those situations is how we react to it.*

**Not all bugs will be caught with testing**

Some issues only emerge with:

- Real traffic
- Real data
- Real users

Script note: *And we are humans, not perfect!*

### Slide 3

**Gradual rollout**

- Deployment
- Staging
- Canary
- Production

Script note: *More opportunities to catch the bug before production. A community of users that help you test a canary version, for example.*

### Slide 4

**Observe the system**

- Logs
- Errors
- Performance
- User feedback

Script note: *Simply tracking NPS or having an online community of your product helps to gather users' feedback.*

- Summarize and group logs
- Compare releases
- Search git history
- Highlight unusual patterns
